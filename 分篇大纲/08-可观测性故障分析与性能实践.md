# 第八篇 可观测性、故障分析与性能实践

《jvm原理》分篇大纲，覆盖第 33—36 章。基于 Java 开发工具包（Java Development Kit，JDK）25，将 Java 虚拟机（Java Virtual Machine，JVM）的机制分析转化为可解释的观测、诊断和性能评估方法。章、节编号与[全书大纲](../大纲.md)对应。

## 本篇目标与前后衔接

本篇沿“选择证据 → 关联时间线 → 排查假设 → 定位原因 → 评估改变”展开。读者应能说明每项诊断数据代表什么、缺少什么，以及为什么某项改变能够改善特定问题。

- 前置知识：前七篇的内存、编译、回收、同步、线程、启动与本地调用机制。
- 核心成果：诊断工具选择表、故障分析案例、性能评估记录和原因解释。
- 案例原则：保留环境、原始证据、推理过程、替代解释和适用条件；结果在正文阶段实际取得。

工具能力与平台限制以 [JDK 25 诊断工具指南](https://docs.oracle.com/en/java/javase/25/troubleshoot/diagnostic-tools.html)为依据，诊断操作的选择同时考虑所需信息和运行开销。

## 第 33 章 JVM 的可观测性与诊断接口

**核心问题：面对一个运行现象，哪一种数据最有助于区分可能的原因？**

### 33.1 统一日志

- 33.1.1 解释标签集合、级别、时间戳和线程信息，按加载、编译、回收及安全点组织问题入口。
- 33.1.2 分析输出目的地、轮转和运行时配置，说明日志量与定位价值的关系。

### 33.2 诊断命令、转储与内存统计

- 33.2.1 对照 `jcmd`、线程转储、堆转储、类直方图和本地内存跟踪（Native Memory Tracking，NMT）。
- 33.2.2 区分结构快照、事件记录和汇总计数，说明停顿、采样及统计范围对结果的影响。

### 33.3 工具接口、插桩与附加

- 33.3.1 介绍 Java 虚拟机工具接口（Java Virtual Machine Tool Interface，JVMTI）、Instrumentation 和 Attach 的职责。
- 33.3.2 说明事件回调、类变换、诊断连接与目标进程之间的关系，记录版本配置和能力限制。

### 33.4 类变换与重定义

- 33.4.1 区分加载时变换、重转换和重定义发生的时机及输入来源。
- 33.4.2 分析允许改变的范围、字节码验证与编译代码依赖，说明工具操作也可能改变被观察对象。

### 33.5 观测方法的开销与偏差

- 33.5.1 对照统计采样、方法插桩、持续日志和转储的时间与空间成本。
- 33.5.2 分析采样间隔、阈值、事件丢失和观察者效应，说明没有记录不等于没有发生。

### 33.6 JDK 25 的兼容性变化

- 33.6.1 整理监控计数器移除或更新方式变化对既有工具的影响。
- 33.6.2 对照传统与虚拟线程相关转储的输出和能力，避免假设不同命令包含完全相同的信息。

例如 JDK 25 调整了部分性能计数器，并增强了部分线程转储的锁信息；具体选择以发布说明与目标进程帮助为准。[发布说明](https://www.oracle.com/java/technologies/javase/25-relnote-issues.html)、[`jcmd` 文档](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jcmd.html)

**图解安排：**问题到证据的选择图、工具与运行时接口关系图、事件与快照时间线。

## 第 34 章 飞行记录器的事件、采样与方法追踪

**核心问题：怎样把分散的运行时事件组织成解释延迟或资源消耗的时间线？**

### 34.1 事件、缓冲与输出

- 34.1.1 介绍 JDK 飞行记录器（JDK Flight Recorder，JFR）的事件产生、线程缓冲、汇集和保存。
- 34.1.2 说明记录配置、阈值、栈深度、数据保留和输出文件对观察范围的影响。

### 34.2 持续记录与上下文

- 34.2.1 对照持续记录、按需导出和事件流，说明各自适用的分析时效。
- 34.2.2 规划自定义事件与上下文关联，将业务阶段和底层运行时活动放到同一时间线上。

### 34.3 跨子系统事件关联

- 34.3.1 关联线程等待、对象分配、编译和垃圾收集（Garbage Collection，GC）事件。
- 34.3.2 区分同时发生、可能相关和存在机制依据的因果解释，规划排除替代原因的证据。

### 34.4 协作式采样

- 34.4.1 分析采样请求、线程协作和安全栈遍历之间的关系。
- 34.4.2 解释安全点偏差及其缓解目标，避免将协作式采样描述为任意情况下都无偏差。

### 34.5 方法计时、追踪与处理器时间画像

- 34.5.1 区分墙钟时间与中央处理器（Central Processing Unit，CPU）时间，以及计时、调用追踪和统计采样。
- 34.5.2 说明方法插桩范围与成本，记录 CPU 时间画像的实验状态和平台条件。

JDK 25 的 CPU 时间画像为实验性 Linux 特性；协作式采样和方法计时追踪分别解决不同观测问题。[JDK 25 监控改进](https://www.oracle.com/java/technologies/javase/25-relnote-issues.html)

### 34.6 记录分析工具

- 34.6.1 使用 `jfr` 的摘要、元数据、事件筛选和聚合视图解释记录内容。
- 34.6.2 使用 JDK Mission Control（JMC）浏览时间线、热点和关联事件，同时保留可追溯的原始记录。

命令选题按 [JDK 25 `jfr` 文档](https://docs.oracle.com/en/java/javase/25/docs/specs/man/jfr.html)组织。

**图解安排：**事件缓冲到记录文件的数据流图、请求延迟关联时间线、墙钟与 CPU 时间对照图。

## 第 35 章 常见故障的原理与定位

**核心问题：怎样把症状逐步缩小为可以解释和修复的具体原因？**

### 35.1 不同区域的内存增长

- 35.1.1 对照堆存活集增长、加载器保留、元空间增长和直接内存耗尽。
- 35.1.2 用持有路径、支配关系、NMT 差异和进程统计区分泄漏、缓存、突发分配与空间未归还。

### 35.2 CPU 高占用与编译异常

- 35.2.1 关联进程、线程、热点方法和采样栈，区分业务计算、忙等、回收及编译工作。
- 35.2.2 分析死循环、频繁去优化与重编译，说明单次线程栈不足以证明持续热点。

### 35.3 死锁、锁竞争与线程资源

- 35.3.1 区分环形等待、长期持锁、条件等待和调度不足，按持有者与等待者建立关系图。
- 35.3.2 分析载体占用、固定和本地线程创建失败，并记录工具对虚拟线程与死锁检测的能力边界。

### 35.4 暂停、分配停顿与容器终止

- 35.4.1 将安全点到达、暂停内工作、并发回收和分配等待分别定位。
- 35.4.2 对照容器限制、进程内存账本和系统终止记录，区分虚拟机异常与外部终止。

### 35.5 崩溃日志与本地线索

- 35.5.1 阅读 `hs_err_pid` 类崩溃报告中的版本、线程、问题帧、动态库和运行参数。
- 35.5.2 结合本地调用、编译代码和资源状态提出假设，说明报告中的问题帧不一定就是最初破坏内存的位置。

### 35.6 从假设到原因定位

- 35.6.1 组织症状、已知事实、候选原因、区分证据与下一步观察。
- 35.6.2 分开描述修复原因和缓解症状，评估改变后的业务表现、资源成本及剩余不确定性。

**图解安排：**内存问题分类树、线程等待关系图、延迟分解图、故障推理记录示例。

## 第 36 章 性能分析方法与综合案例

**核心问题：怎样证明一项性能改变改善了目标，同时理解它付出的成本？**

### 36.1 目标与测量口径

- 36.1.1 定义吞吐量、延迟分布、启动时间和资源占用的统计范围。
- 36.1.2 说明平均值与尾部表现、服务时间与端到端时间的区别，选取符合应用目标的指标。

### 36.2 运行阶段与环境控制

- 36.2.1 分开记录冷启动、预热和稳定运行，控制文件缓存、依赖准备及负载阶段。
- 36.2.2 记录硬件、容器配额、堆参数、并发度和数据规模，使用重复观察区分趋势与偶然波动。

### 36.3 微基准方法

- 36.3.1 介绍 Java Microbenchmark Harness（JMH）的预热、独立运行进程和测量组织方式。
- 36.3.2 分析死代码消除、常量折叠、状态共享、循环放大和计时开销，说明微基准结论的适用范围。

### 36.4 分配、存活与收集器选择

- 36.4.1 结合分配速率、存活集、回收进度及空间余量解释瓶颈。
- 36.4.2 在相同资源预算下讨论收集器取舍，同时衡量业务时延、吞吐量和总内存。

### 36.5 容器资源与运行时配置

- 36.5.1 分析 CPU 配额、线程并行度和后台编译及回收线程的共同竞争。
- 36.5.2 将堆、栈、元空间、代码缓存和本地分配纳入容量预算，解释为什么单改堆上限可能转移问题。

### 36.6 综合案例组织

- 36.6.1 按启动与预热、分配与回收、同步与虚拟线程、本地内存与容器四组案例串联全书。
- 36.6.2 每组案例保留改变前后的相同观测口径，说明改善机制、额外成本、失败条件和可推广范围。

**图解安排：**测量阶段图、指标与资源权衡图、综合案例的机制与证据对应图。

## 实验与综合案例计划

| 对应章节 | 选题 | 主要证据 | 结论边界 |
| --- | --- | --- | --- |
| 第 33 章 | 同一现象的不同观测方式 | 日志、事件、汇总和转储 | 比较工具提供的信息而非简单比较输出多少 |

## 全书结束时应形成的能力

- 从语言规范判断程序允许的行为，从源码解释具体实现的运行机制。
- 按问题选择观测工具，理解时间、空间及抽样口径，避免用不完整数据过度归因。
- 将改动的收益与代价放回明确的负载、版本和部署条件，形成可复查的分析记录。

附录继续提供术语、字节码、参数命令、源码导航、历史机制和阅读路线索引。
