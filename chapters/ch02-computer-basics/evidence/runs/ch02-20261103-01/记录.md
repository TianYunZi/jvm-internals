随后在允许系统诊断的命令环境对实际进程号 15162 执行：

```sh
ps -p 15162 -o pid,ppid,arch,%cpu,rss,vsz,etime,command
ps -M -p 15162

vmmap 15162
jcmd 15162 Thread.print -l
jcmd 15162 GC.heap_info
jcmd 15162 VM.native_memory detail scale=KB

```

`jcmd` 实际使用与启动进程同一 JDK 主目录的 `bin/jcmd`，完整固定目录见上方 java 路径。各自输出重定向到同目录 process.txt、system-threads.txt、vmmap-summary.txt、vmmap.txt、java-threads.txt、heap.txt、native-memory.txt、vm-flags.txt。

实际问题：本机 `ps` 不支持 arch 关键字，错误信息为 `ps: arch: keyword not found`，仍打印了其余列；后续运行改用支持的列。vmmap 与系统线程文件成功取得。虚拟机附加命令则抛出 AttachNotSupportedException，无法打开目标临时目录内的 .java_pid15162；os-threads.log 中多次出现 Attach Listener 退出，批量诊断最终退出 1。没有把失败命令写成成功。

本次原生命令可供比较环境差异，但正文主数字引用 O02，不混用两个进程的地址。启动权限对附加通道的影响是受限条件下的推断；不能单凭错误字符串证明所有环境中存在唯一根因。下一次只调整启动的执行权限并修正 ps 列，保持源码、输入、堆及跟踪配置不变，单独留证，不覆盖本目录。
