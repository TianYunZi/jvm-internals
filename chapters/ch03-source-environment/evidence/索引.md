## 加载阅读路线

1. O01 调试器在应用入口之前实际停在 `ClassFileParser::parse_stream`，本地栈包括 `SystemDictionary::load_instance_class`、`load_instance_class_impl`、`ClassLoader::load_class`、`KlassFactory::create_from_stream` 和解析器构造。
2. 实际读取 `src/hotspot/share/classfile/klassFactory.cpp` 的 `create_from_stream`（170 起）：以 ClassFileStream、名字、加载器数据和 ClassLoadInfo 进入；普通情况下处理加载钩子，再构造 ClassFileParser、创建 InstanceKlass。隐藏类与其他条件的完整语义交 CH08，未把本轮未记录参数补成具体类型。
3. `classFileParser.cpp` 的 `parse_stream` 按结构消费字节；此前 CH04 已核对其版本、常量池、成员与属性分派。解析器函数名存在、源代码关系与本次动态停靠分别给出依据。
4. 应用 ProgramJourney 与 Payload 的类名来自实际 class-load.log；没有把它们归给未读取参数的原生断点。

## 分配阅读路线

1. 本轮启动条件 `-Xint -XX:-UseTLAB` 已记录。线程本地分配缓冲区（Thread-Local Allocation Buffer，TLAB）关闭是本次观察选择，不是默认执行条件。
2. 实际读取 `src/hotspot/cpu/aarch64/templateTable_aarch64.cpp` 的 `TemplateTable::_new`（3597 起）：模板先生成检查与分配代码，UseTLAB 条件决定生成的快路径；慢分支生成对 InterpreterRuntime::_new 的调用（3691）。不能把模板生成函数写成每次 Java new 的普通运行时调用。
3. 实际读取 `src/hotspot/share/interpreter/interpreterRuntime.cpp` 的 `_new`（214 起）：从常量池获得 Klass、转换为 InstanceKlass、检查可实例化、初始化、调用 allocate_instance，并设置运行时返回对象。
4. 实际读取 `src/hotspot/share/oops/instanceKlass.cpp` 的 `allocate_instance`（1582）：取得 size_helper，转交 Universe::heap()->obj_allocate。下游关系为源码依据，不补造未采集的本地栈。
5. O01 动态停在 `_new`，其下数个生成代码地址没有普通函数名；本轮没有从地址反推出具体 Java 类或方法。断点发生在应用 main-enter 之前，不标成 Payload 的指定对象。
