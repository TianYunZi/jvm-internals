# 布局工具身份与构建

Java Object Layout（JOL）官方仓库 https://github.com/openjdk/jol.git；实际提交 db2cc744485031c8149991a004ab02f2ea9b24dd，根 pom.xml 声明 0.18-SNAPSHOT。本书的 Maven 本地坐标 org.openjdk.jol:jol-core:0.18-db2cc744 是本地构建标识，不是 Maven 中央仓库正式发布版本。2026-11-03 实际读取中央仓库元数据，正式发布最高 0.17（2023 年），未用它支撑紧凑布局。

已核查 CurrentLayouter 使用 Unsafe 字段偏移与数组偏移，HotspotUnsafe.guessHeaderSize 读取样本首字段位置，guessLilliput 检测头中类型信息，ModelVM／classPointerSize 在紧凑模式取消独立类字，InstrumentationSupport 支持启动代理取对象大小。第三方代码没有修改。

## 可重建材料

本目录 jol-core-db2cc744-source.tar.gz 保留原提交的 jol-core/src/main、根与模块 pom.xml；LICENSE 与 THIRD-PARTY 为原资源副本。源码版权和许可证完整保留；不把官方工具当作本书自编教学源码。外部研究克隆在 artifacts/tool-sources/jol，普通检索排除。归档足以重建核心生产工具，不依赖临时下载或已编译的工具目录。

实际构建工作目录为项目根目录：

```sh
git clone --depth 1 --filter=blob:none --sparse https://github.com/openjdk/jol.git artifacts/tool-sources/jol
git -C artifacts/tool-sources/jol sparse-checkout set jol-core/src/main
git -C artifacts/tool-sources/jol rev-parse HEAD
mkdir -p artifacts/tool-build/jol/classes
rg --files artifacts/tool-sources/jol/jol-core/src/main/java -g '*.java' > artifacts/tool-build/jol/sources.txt
task_jdk=/opt/homebrew/Cellar/openjdk@25/25.0.5.0.2/libexec/openjdk.jdk/Contents/Home
"$task_jdk/bin/javac" -source 8 -target 8 -d artifacts/tool-build/jol/classes @artifacts/tool-build/jol/sources.txt
```

实际 HEAD 为上列固定提交；复建时须检出该提交而非任意新 HEAD。也可解压本目录归档到工具工作目录，直接使用相同源文件。构建退出 0，源码目标为工具原工程的 Java 8，编译器为本机 JDK 25；原始弃用与 Unsafe 警告完整保存于 compile.txt。没有编译或执行第三方测试，没有改工具源码以消除警告。

生成 manifest.mf 的实际内容：

```text
Manifest-Version: 1.0
Premain-Class: org.openjdk.jol.vm.InstrumentationSupport
Implementation-Title: OpenJDK JOL core
```

空行结束清单；随后执行：

```sh
"$task_jdk/bin/jar" --create --file chapters/ch10-object-layout/evidence/tools/jol-core-db2cc744.jar --manifest artifacts/tool-build/jol/manifest.mf -C artifacts/tool-build/jol/classes . -C artifacts/tool-sources/jol/jol-core/src/main/resources .
JAVA_HOME="$task_jdk" mvn -B -ntp -N org.apache.maven.plugins:maven-install-plugin:3.2.0:install-file -Dfile=chapters/ch10-object-layout/evidence/tools/jol-core-db2cc744.jar -DgroupId=org.openjdk.jol -DartifactId=jol-core -Dversion=0.18-db2cc744 -Dpackaging=jar -DgeneratePom=true
```

原首次安装因沙箱网络缺少插件依赖失败，install.txt 保留；允许网络后 install-network.txt 退出 0。Git 归档第一次也因需懒取尚缺对象失败，联网后同提交归档成功。正式工具和归档的完整安全哈希算法 256 位（Secure Hash Algorithm 256-bit，SHA-256）值在运行目录 input-sha256.txt；本地坐标不可独立代替摘要。

## 使用边界

运行使用 -javaagent 显式启用工具自己的启动代理，避免动态附加；-Djol.skipHotspotSAAttach=true 不尝试 HotSpot 服务性代理（Serviceability Agent，SA）。所以 JOL 打印的引用基址／位移是猜测，地址不可作为实测，原警告不删除。对象引用位移另从 HotSpot 启动日志取证。

JOL 的 ClassLayout.parseMarkWord 仍按旧位移 8 解码哈希，并使用旧状态术语；当前 HotSpot markWord.hpp 的 hash_shift 为 11。故只使用其原始头字节、字段偏移、数组起始位置与大小，不据它的 hash／age／non-biasable／experimental 字样判定当前状态或特性等级。产品状态、状态位和协作协议依据锁定 HotSpot 与官方 JEP 文档。未修改工具来伪造完整兼容。
